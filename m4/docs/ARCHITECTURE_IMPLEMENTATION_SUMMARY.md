# Codely M4 Task 10 · Architecture Intelligence

## Objective and completed M4 work

Turn trusted M3 structural analysis into source-grounded architecture advice and give M2 and M1 a validated contract for consuming it. M4 implements the graph adapter, the guidance registry, the advice worker, and the offline frontend handoff.

1. The M3 compatibility adapter projects Python modules and uniquely resolved internal imports into `ObservedGraph`. It preserves stable identifiers, source ranges, cycles, coverage, unresolved references, and omission reasons. Projection is deterministic and bounded to 15 nodes and 20 edges.
2. Registry v1.0.0 contains 11 engineering guidelines with source references, applicability, limitations, benefits, and trade-offs. It references four existing M3 checklist IDs without reimplementing checklist evaluation. Graph, source, framework, and requirement signals select relevant guidance. Mandatory status requires trusted server configuration.
3. The M2 worker compares the authorized identity, captured snapshot, and separately stored report binding before accessing source or calling the configured provider. It uses the existing M4 advice engine. Response validation checks graph endpoints, component and evidence citations, and selected guideline IDs.
4. The M1 handoff includes TypeScript interfaces, an observed graph DTO adapter, and five JSON examples. Recommendations, proposed nodes, and proposed edges stay separate from observed source-backed elements. A simulated unavailable provider leaves the observed graph intact.

## Security and remaining team work

M2 owns authorization, immutable snapshots, report provenance, freshness, trusted policy, and provider lifecycle. M4 rejects mismatched bindings and reads canonical source only from the captured snapshot. Matching metadata checks consistency and does not independently attest provenance. Static Python evidence and the selected subgraph cannot establish all runtime relationships. Guidance is advisory unless explicitly configured as policy, and proposed changes require developer review.

The submission excludes local credentials, `.env` files, caches, model weights, indexes, sensitive logs, and private source. The committed M3 source fixtures are from a public pinned revision.

- **M2:** Call the advice worker from a project-aware service and expose the advice envelope without breaking the existing observed-graph contract. Supply trusted snapshot and report bindings and retain observed data when advice is unavailable.
- **M1:** Reuse the existing viewer and source navigation, then wire advice, proposal overlays, coverage, and provider states to the M2 response.
